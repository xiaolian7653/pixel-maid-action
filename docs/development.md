## 三、操作与状态机

- 键盘：`A/D` 或 `←/→` 移动，`Shift` 奔跑，`S/↓` 匍匐（不按方向为蹲下），`空格/W/↑` 跳跃，`J` 攻击，`H` 受击，`K` 倒地，`R` 复活，`Q` 待机Ⅱ。
- 触屏：左下 ◀ ▶ 移动 + 蹲/匍匐；右下 奔跑（按住）、攻击、跳跃；中间帧速滑块与调试小键。
- 状态流转：自由态（待机/行走/奔跑/蹲下/匍匐）内允许起步、收步、急刹、转身；攻击段内再按可连下一段；受击有短时无敌帧；倒地后进入 `dead` 保持姿态。

## 四、横屏适配经验（本次重点复盘）

### 4.1 现象

手机上打开页面不横屏；旋转屏幕后页面不跟随，看不到任何方向识别；全屏锁定按钮无效。

### 4.2 根因

1. **容器 / 部分 webview 不派发旋转事件**：只监听 `resize`、`orientationchange` 时，屏幕转了事件也不来，页面停在初始方向。
2. **方向信号不可盲信**：`screen.orientation.type` 在被锁定竖屏的容器里恒为 `portrait`；`window.orientation` 仅老 iOS 可靠。
3. **全屏与方向锁定在移动端能力受限**：iOS Safari 不支持元素全屏，也不支持 `orientation.lock`；webview 里 `requestFullscreen` 常被拒绝。不能把“锁定方向”作为横屏的唯一手段。
4. **伪横屏下媒体查询失效**：整页被 CSS 旋转后视口仍是竖屏，`@media (max-height: …)` 按视口计算，收小按键的规则不会触发。

### 4.3 最终解法（按优先级落地）

1. **多信号 + 轮询兜底**：同时监听 `resize`、`orientationchange`、`visualViewport.resize`、`screen.orientation.change`、`pageshow`、`focus`，再叠加 **400ms 轮询**巡检，事件丢失也能发现尺寸 / 方向变化。
2. **方向判定优先级**：
   - 宽高比 `长/短 > 1.12`：直接按 `width > height` 判横竖（最可靠，绕开假 orientation 值）；
   - 否则读 `screen.orientation.type`（`landscape*`）；
   - 再否则读 `window.orientation`（`±90` 为横屏）；
   - 最后回退宽高比较。
3. **竖屏伪横屏兜底**：舞台 `position: fixed`，`left/top: 50%`，`translate(-50%,-50%) rotate(90deg)`，`transform-origin: center center`；`width = 视口长边`、`height = 视口短边`。不依赖全屏 API，容器锁竖屏也能把画面横过来。
4. **手动切换 + 自动交还**：提供「横置 / 竖置」手动键；一旦检测到设备真的转过方向（landscape 判定翻转），自动撤销手动覆盖，避免手动模式一直锁死。
5. **全屏 / 锁定只做 best-effort**：`requestFullscreen` / `webkitRequestFullscreen` / `screen.orientation.lock` 全部 `try/catch`，失败静默降级到伪横屏。
6. **紧凑档位用元素 class，不用媒体查询**：短屏（等效高 `< 440`）给舞台加 `.compact` class 收小按键；媒体查询在伪横屏下不生效。
7. **检测结果上屏**：HUD 显示「竖屏·已横置 390×844 / 横屏 844×390」，真机出问题先读这组宽高和方向，直接定位是检测错还是样式错。
8. **提示层位置**：方向提示放进被旋转的容器内；不要在未旋转的固定层上放横屏浮层，否则方向错位、遮挡按键。

### 4.4 性能细节

- 布局重算前用 `宽高 + rotate 状态` 拼 key 缓存，状态没变就不重写 `style`，避免每 400ms 一轮重排。
- 横屏复位时用 `style.cssText = ''` 清空内联覆盖，回到原始 100% 流式布局。

## 五、帧利用率复盘：蹲下 / 匍匐 / 跳跃 的 80 帧是假的

### 5.1 现象

HUD 显示「帧 x/80」，但蹲下和匍匐几乎不动；匍匐甚至长时间停在「1/80」。

### 5.2 两个独立根因

1. **虚帧**：`slots(list, 80)` 把 6 张蹲下、8 张匍匐的图按比例拉成 80 帧，实际只有 6 / 8 个不重复姿态，其余 74 帧是同一张图重复。
2. **匍匐根本没推进**（更要紧的 bug）：`freeResolve()` 里按住方向 + 按下键时，每帧都执行 `setState('crawl')` 并把 `animDist = 0`。帧索引由 `animDist / 步距` 计算，步距又被重置，于是永远 `floor(0) = 0`，画面卡在第 1 帧——80 帧一张也没播过。蹲下走的是 `slider` 分支按时间推进，所以看起来在动。

### 5.3 修法（照奔跑的挑帧法重排）

1. **先量化重复度**：对每帧算 alpha 剪影的 IoU 差异矩阵。匍匐 u3/u8 与相邻帧重合度约 0.93，属于重复帧；蹲下 p1/p6、p3/p6 同样近乎重合。
2. **按平滑度选循环**：在 8 帧里穷举 6 帧的所有环形排列，取相邻帧差异总和最小的顺序 → `u1→u2→u4→u5→u7→u6`（与奔跑抽 `z1,z2,z4,z5,z6,z8` 跳掉两张同款帧完全同一思路）。
3. **循环长度要真实**：蹲下 4 帧、匍匐 6 帧、跳跃 8 帧，HUD 直接显示真实总帧数。
4. **步距随循环长度改**：匍匐原为 `120/80`（1.5px 一帧），改为 `72/6`（12px 一帧），6 帧一圈走 72px，约 7fps、1.15 圈/秒。
5. **状态推进要区分「一次性动作」和「保持循环」**：固定 fps 的动作走到末帧会调 `finish()` 收招；蹲下是保持态，另开 `DEF.loop` 分支做取模循环，否则会在末帧卡死。
6. **进入态才重置步距**：`if(state!=='crawl'){ animDist=0; setState('crawl'); }`，而不是每帧无条件重置。

### 5.4 教训

- 用 `slots()` 凑帧数（把 6 张拉到 80 张）能骗过 HUD，但骗不过眼睛；真实可用的帧数必须来自不重复的姿态。
- 位移驱动的循环动画（walk / run / crawl）要检查「帧索引是否真的在推进」，光看画面像在动（平移 + 交叉淡化）容易漏掉帧索引卡死的 bug。
- 一次性动作与保持动作要分开推进逻辑，否则固定 fps 会误触发 `finish()`。

### 5.5 行走步态修正（第二轮）

三个可量化毛病，逐一改：

| 指标 | 实测 | 原实现 | 修正后 |
| --- | --- | --- | --- |
| 触地姿势双脚分开 | 61–67px | 步距按 200px/圈 | 120px/圈（≈2×61） |
| 每帧位移 | 应 15px | 25px（每帧多滑 10px） | 15px，150px/s 恰好 10fps |
| 上身重心横向漂移 | 75.9–84.9px（9px 摆幅） | 不做补偿，躯干左右抽 | 按均值补偿 60% 的 `dx` |
| 上下起伏 | 接触低、过渡高 | 无 | `bob` +1.2 / −1.0 画布像素 |

要点：

1. **步距由帧里的脚决定**，不能拍脑袋给 200px：`px = 一圈距离 / 帧数`，再由 `速度 / px` 反推帧率，支撑脚才不打滑。原来 25px/帧、真步长 15px，等于每帧往后滑 10px，加上只有 6fps，就是“原地滑步”。
2. **躯干锁定用剪影实测**：取上身（y 18–72）质心，按均值做部分补偿（60%）；全补偿会把自然的左右承重晃一起抹掉。
3. **起伏只给 1–2 画布像素**，给在触地/过渡帧，超过就变蹦跳。
4. `paint()` 增加 `dx`（水平补偿）参数后，`walkStart` / `walkStop` 也必须用同一套预计算帧（`vFrame()`），否则过渡帧与循环帧姿态会跳。
5. 遗留：过渡帧 v3/v7 抬膝到胯部，偏“行军感”，属于资产问题，数值补不了，需单独重画这两帧压低抬腿幅度。

### 5.6 匍匐改为跪姿爬行（动作语义纠正）

原 u 组是**贴地匍匐（belly crawl）**，整个躯干趴在地上、四肢贴在体侧，语义上与「跪姿爬行」不同。重做流程：

1. **一次成表**：用 `image_edit` 以现有行走帧为画风/配色基准，生成一张 4 帧横排图（不是分 4 次生成），保证同一批帧的配色、比例、位置一致；分次单帧生成必然出现风格漂移。
2. **提示词要写清“否”**：只说“跪姿爬行”模型会退回趴姿，必须显式写「双膝着地并拢、双手撑地、大腿竖直、臀部抬到与背平、不要向后抬腿、不要踢脚朝天、不要趴在地上、头抬起」。
3. **切片**：按列占用找 4 个连通区间切分（不靠固定等宽），再对每格做白底连通域抠除 + 中性灰地面条剔除 + `<18px` 孤块清理。
4. **归一**：整组按同一比例缩放到最高帧 72px，底部对齐基线 118（最低不透明行 117），避免各帧踩地不一致。跪姿本就比站姿矮（72 vs 80），不要拉到同样高度。
5. **循环与步距**：4 帧手膝交替（双手撑地 → 右手前摆 → 双手撑地 → 左手前摆），`px = 44/4 = 11`，按 82.5px/s 得约 7.5fps。
6. 生成图的像素密度比原精灵柔，缩小后边会略糊；可加中值色调色板量化（32–48 色、无抖动）变硬边，但会损失一点高光，按需取舍。

### 5.7 帧间一致性归一（解决“卡帧”观感）

AI 逐张生成的帧，即使同一次出图，四格之间的角色大小、身体位置也会有 3–7px 漂移；循环播放时身体会一跳一跳，看起来像卡帧而不是在爬。逐项归一：

| 项 | 实测漂移 | 处理 |
| --- | --- | --- |
| 帧高 | 71 / 72 px 混用 | 统一缩放到 72px（同组等比） |
| 帧宽 | 99–105 px | 随高度等比缩放，不再单独拉伸 |
| 上身重心 x | 81.5–87.6（约 6px） | 全部对齐到组内均值 83.5 |
| 着地点 | 最低行 117 | 统一贴基线 118 |
| 播放节奏 | 4 帧跑 7.5fps | 步距改 66px/圈 → 约 5fps |

要点：

1. **先归一，再讨论动作**：把高度、基线、上身重心三个锚点锁死，剩下的差异才是“该动的部分”（手臂、翅膀）。
2. **锚点要选稳的**：用上身（上 55% 高度）剪影质心，比整帧 bbox 中心稳，不会被伸手/抬腿带偏。
3. **慢下来比补帧更有效**：4 帧 7.5fps 等于每秒闪 7 次姿态，任何一点形变都会被放大；降到 5fps 后同样的帧看着顺很多。
4. **别指望模型给出像素级一致**：`image_edit` 说“只改手臂”仍会重画头发和裙摆。想真正一致，要么一次出整张表（本组做法），要么接受逐帧漂移后用上面的锚点归一兜住。
5. 顺手修了个状态机漏洞：**行走/奔跑中按方向键 + 蹲键不会进跪爬**（`freeResolve()` 的 walk/run 分支提前 return，压根没看 `input.down`）。现在在走/跑分支里先判 `input.down`，直接切 `crawl`。

### 5.8 跳跃相机跟随

舞台是 960×360，角色高约 320（`80px × SCALE 2`），留白只有 40px；起跳最高约 61.6px（`JUMP_V²/2GRAV`），不做相机跟随角色会顶出画面上沿。

做法：

1. **只跟随一半**：`cam.ty = player.y * 0.50`，保留 50% 的可见上升量，纯 100% 跟随会让角色看着“原地不动、世界在沉”。
2. **轻微拉远**：顶点最多 `zoom 0.94`，给上下都留出空间，幅度超过 10% 会有明显镜头畸变感。
3. **指数阻尼**：`k = 1 - exp(-dt × 9)`，时间常数约 0.11s。角色 0.57s 滞空里相机慢半拍跟上，正好产生“先冲出去、镜头再追上”的弹性感；线性 lerp 会显得机械。
4. **落地回正**：目标值归零，同样用阻尼回位；偏差小于 0.15px 直接吸附，避免永远抖动。
5. **视差参照物**：纯暗背景里相机平移是看不出来的，加 38 颗 1–2px 远景星点，只吃 40% 的相机位移（`y - cam.y*0.6`），地面吃 100%，眼睛才有纵深参照。
6. **变换顺序**：`clearRect → shake → 相机(translate 中心 → scale → translate 回中心)`；地面线、粒子、角色都在同一坐标系里，自动跟着相机走，不用逐项补偿。

调试坑：canvas 上的精灵来自跨域 CDN，`getImageData` 会抛 `SecurityError`（画布被污染），验证相机只能靠截图比对，或临时挂一个 `window.__dbg()` 读 `player.y / cam.y / cam.zoom`，验完删掉。

### 5.9 待机卡帧（重复帧 + 横向甩动 + 节奏）

现象：待机循环看着“顿一下、不连贯”。量化后有两条硬缺陷：

1. **重复帧**：源表 `m` / `n` 各只有 8 张图，`slots(M,11)` 却拉成 11 帧，索引映射为 `0,0,1,2,2,3,4,5,5,6,7` ——环里夹了 3 个**同画连播**，每个都是一次 1 帧的停顿。改回 8 张唯一帧。
2. **横向甩动**：8 帧上身剪影质心 76.5–81.6，相对均值最大偏 3.25px，等于每换一帧整个人左右跳一下。用 `dx = -0.9 × 偏移 × K` 锁死（走路那套 60% 补偿的加强版，待机允许保留一丁点惯性）。
3. **顺序**：把 8 帧的环按相邻剪影差异最小重排（1→8→3→7→2→6→4→5），环上总差异 2.064→1.700，平均单步 IoU 0.71→0.79。
4. **节奏**：帧速滑块默认 12 → 8fps（一圈 1s）；进帧累加器从“清零”改成 `-= step`，避免每次多攒的零头被吞掉导致帧间隔忽长忽短。
5. **换帧软边**：待机单独用 `blendFrom=0.75` + 三次缓出（60Hz 下约 2 帧的融合），只盖住硬切那一瞬，不像走路那样长时间双帧叠加，像素不会糊成重影。

仍未解决的根因：这 8 帧是 8 次独立生成，翅膀角度、发量、躯干倾斜各自不同（两两剪影 IoU 0.62–0.92，帧 4 是离群值）。试过用 `image_edit` 一次出 8 帧整表，两版都能把帧间剪影 IoU 拉到 0.97–1.0，但一是动作幅度小到几乎静止（多帧剪影完全重合），二是画风变成高清渐变版，和其余动作的硬边低色数不搭。所以这次只做几何与节奏归一；要真正“连”起来，得按行走那套重画一张 8 帧待机 sprite sheet。

### 5.10 待机改为「单帧呼吸形变」12 帧

5.9 的去重、锁重心、重排只能消掉机械停顿，消不掉**姿势本身不一致**：8 张图是 8 次独立生成，翅膀角度、发量、躯干倾斜都不同（两两剪影 IoU 0.62–0.92），换帧就是一次硬跳。用 `image_edit` 一次出整表试过三版：都能把帧间 IoU 拉到 0.94 以上，但前者动作幅度小到几乎静止（多帧剪影完全重合），后者画风变成高清渐变版，跟其余动作的硬边低色数不搭。

最后走的是「用一帧做出所有帧」的路子：

1. 取待机 m1 一张图，按**行**做垂直位移，位移量 = `A × s(k) × w(y)`，`A=3px`，`s(k)=(1-cos(2πk/12))/2`（12 帧一个完整吸→呼）。
2. `w(y)` 按高度插值：肩部 1.0、胸 0.9、腰 0.7、裙摆 0.45、膝 0.12、**脚与长靴 0.0**。脚不动是硬约束，重心不漂。
3. 位移取整到像素、最近邻重采样，所以每帧只动 1px：实测相邻帧剪影 IoU 0.94–1.0，且第 0 帧与第 11 帧左右完全对称。
4. 12 帧 × 8fps = 1.5s 一个呼吸周期；上肩抬 3px（屏幕上 6px），肉眼能看出起伏但不会“抽”。

代价：待机固定在一个站姿上，不再有原来的发丝/翅膀变化。换来的是零跳变、零重复帧、零横向漂移。要“既连贯又有多变化”，只能重画一张真正的 8–12 帧待机 sprite sheet，不是生成模型现在能做到的。

### 5.11 打击感与训练木桩

原来四段攻击只是「播动画」：没有命中判定、没有反馈，挥完就回待机。这一版把攻击做成能打的东西。

**木桩**

- 位置 x=700、立在 `GROUND_Y`；纯 `fillRect` 手绘（立柱 / 横臂 / 草绳 / 草头 / 刀痕 / 影子），不依赖外部素材。
- 耐久 130，头顶血条随掉血变色；被打碎后换成「断桩 + 掉落的头 + 断臂」的残骸，2.2s 自动复原。
- 当实体处理：玩家中心与木桩中心距离 <58 时被推开，不会穿模。

**打击感六件套**（每次命中同时触发）

1. **顿帧**：`hitStop = 0.05 + 0.05×pow`，命中瞬间把整帧 `dt` 压到 5%，最短 3 帧、重击约 9 帧。
2. **震屏 + 镜头前推**：`player.shake` 由 0.05 起、重击到 0.18；`camKick` 额外放大 1.4%，按 `0.0006^dt` 衰减，形成一次「怼上去」的呼吸。
3. **火花 + 木屑**：白/粉火星沿命中法线喷出，另加棕黄木屑（重击 9 粒）。
4. **冲击环 + 闪光**：命中点画两圈扇形弧（外圈宽、内圈细），前 45% 生命里叠一层径向渐变白光。
5. **飘字 + 连击**：伤害数字从木桩右侧升起、`combo≥3` 加一条「N HIT」；HUD 常驻连击 / 累计伤害。
6. **音效**：WebAudio 现场合成，命中是带通噪声（760–980Hz）+ 52–120Hz 低频「闷响」，挥空是一记高频短促「咻」；「♪」按钮可关。

**动作本身**

- 出手帧向前压一步（52–70px/s），不再原地挥；木桩受击给弹簧回摆（角速度冲量 1.05×pow，k=34）与位移冲量，约 0.3s 内回正。
- 命中判定按段配置：活跃帧 `[1,2]`（第四段 `[2,3]`）、前方距离阈值 70/84/92/112，每段只结算一次（`hitDone`）。

### 5.12 跪爬手脚协同修复（第二轮）

**旧帧实测毛病**（肤色/轮廓连通域测量）：近手 x 只在 96–117 间小幅移动（约 5px），抬手帧没有另一只手落地支撑，身体悬空；腿部在长裙下完全静止，膝/脚位各帧几乎不变；没有呈现「一手撑地同侧膝前送、对侧手抬起前摆」的对角交替，观感是手臂独立扑腾、腿粘在地上。

**路线取舍**：

1. 再次整表生成被实测否决——新出图腿部交替仍然极弱（靴位左右摆幅源图仅 18px，归一后约 4px），且边缘偏柔、配色往 HD 渐变漂；与本套硬边低色数帧不搭。
2. 改用本地历史表 `crawlsheet.png`（与旧帧同批像素风）：它本来就有明确的腿/膝交替（靴后缘源图 30/92/10/87），且腿后伸帧配对手前撑、收腿帧配对手收肩下，对角关系成立。
3. 旧表自带白色女仆荷叶边裙摆 + 白底光晕，做了三步清理：白底 >225 转透明；边缘近白非肤色像素按邻域透明判为光晕去透明；左下裙区浅白荷叶边改裙装深色（胸挡白、袖口白保留，与行走帧一致）。

**锚点归一**：

- 旧跪爬源帧高 71px（站姿 96px），新帧统一缩到源高 71、贴基线 118，不拉伸到站姿高度；帧宽 91–106px 随姿态等比。

- `bob` 改为支撑 0 / 过渡 −0.6，`dx` 左右 ±1.5 补偿重心；步距维持 66px/圈。

**遗留**：裙摆荷叶边残留一圈浅灰细边；发尾带一个小卷环，行走帧没有——属资产细节，数值层面补不掉，需后续单独重画这两组帧时再对齐。

### 5.13 冲刺 6 帧 + 冲刺收势 6 帧

新增一个突进动作：`dash`（6 帧突进）→ `dashEnd`（6 帧收势回站），非循环、按帧速计时推进，不走 `animDist` 步态分支。

**帧资产**

- 两张 6 格横排整表分别生成（突进表 / 收势表），参考奔跑帧锁定服装配色；深灰蓝底抠除后裁边、贴基线 118、按站姿源高归一。
- 突进 6 帧：蹬地压低 → 低位跨步 ×3 → 前倾峰值 → 略收；收势 6 帧：前倾残留 → 重心回拉 → 上身回直 → 脚步收住 → 躯干回正 → 接近站立。
- 翅膀调色板偏浅（生成图翼色 R 170–194，参考奔跑翼色均值约 107/64/63），按「上半区左半、排除粉发/肤色/白色」的翼部掩膜向参考翼色压暗；收势帧翼面被身体头发遮挡较多，可见翼面积偏小，属资产残留。

**状态机接入**

- 触发：自由态（含 walkStart/runStart）按 `L` 或面板「冲刺」按钮；触发时按当前方向键定朝向。
- 速度：突进 `DASH_V=360`，收势初速 `DASH_END_V=250` 后按 `0.02^dt` 衰减；突进帧随机扬尘。
- 流转：`dash` 播完 → `dashEnd`；`dashEnd` 播完 → 方向仍按住则 `runStart/walkStart`，否则回 `idle`。
- 受击/攻击/跳跃守卫把 `dash*` 一并排除，冲刺途中不能插攻击或跳。

**手感补强**

- **残影拖尾**：突进中每 45ms 抓一帧当前姿态存入 `afterimages`，半透明（峰值 0.4）滞后 0.35s 淡出，按各自朝向翻转，渲染在本体身后。
- **扬尘与启动反馈**：起手爆发 5 粒扬尘 + 镜头前推 `camKick=0.012`、轻震 0.05；突进途中每帧 2 粒脚下扬尘。
- **撞击击退**：冲刺途中单次接触木桩（前方 70px 内）给角速度/位移冲量 + 木屑火花 + 0.03s 顿帧，不计连击与伤害；`dashHit` 每轮冲刺重置。

**遗留**：新帧胸前白围裙片与裙摆浅灰荷叶边比行走帧明显；收势帧翅膀偏稀疏。

### 5.14 冲刺帧资产与行走帧风格统一

针对 5.13 遗留的围裙白片、裙摆荷叶边、翅膀偏浅问题，在本地 12 帧（A0–A5 突进 / B0–B5 收势）做程序化调色，未新增功能。

**量化基线**：行走/奔跑/攻击参考帧白像素 88–235、裙边白 13–31、翼色均值约 (70,42,42)；冲刺帧调色前白像素 494–577、裙边白 240–284，收势翼色偏浅 (101,51,53)。

**调色规则**
- 掩膜：粉发 `R>200 & G∈[100,190]`；肤色 `R>180 & R-G>18 & G-B>5`，其余浅色非肤非发判定为围裙/荷叶边。
- 围裙片与裙边：下半区（y≥70）、中线以左（x≤100，右侧袖口白保留）压成裙装深色 `(35,28,29)`，与参考裙装均值对齐；上半胸 bib 白与袖口白保留。
- 翅膀：上半区左半翼部掩膜按参考翼色 (70,42,42) 压暗，因子限 0.5–0.9 避免死黑。

**结果与残留**

### 5.15 收势帧翅膀移植补密

### 5.16 头发 / 裙摆动作协同摆动

在不新增动作、不改玩法的前提下，给发梢与裙摆加一套滞后跟随弹簧。

**分层做法**
- 帧加载后把每张帧画布拆成 `base`（身体/皮肤/白袖/靴子/翅膀）与 `cloth`（粉色头发 + 腰到下摆带 y56–92 的深色裙片）两层；靴子 y>92 与翼部区域保持刚性，不参与摆动。
- 图片请求带 `crossOrigin='anonymous'`（CDN 已返回 `access-control-allow-origin: *`），否则画布被跨域污染、`getImageData` 取不到像素。

**跟随曲线**
- 待机：发梢/下摆按 1.7rad/s 轻摆，幅度 ±0.7 帧像素。
- 行走/奔跑/跪爬：布料滞后于移动方向，偏移 0.8–2 帧像素；冲刺拖尾 3 帧像素，收势 1.6。
- 跳跃：水平滞后 1，上升轻抬、下落微压；落地压缩由 `landT` 再向下带 1 帧像素。
- 攻击：出手帧沿拳向轻甩 1.2，收招回弹 0.5；受击/倒地随击退方向偏移。
- 弹簧刚度 22、阻尼按 `0.002^dt` 衰减，避免果冻感；渲染时 base 按姿态贴出，cloth 叠加 `hx/hy` 偏移。

**回归**：待机/走/跑/跪爬/蹲/跳/四段攻击/受击/倒地/复活/冲刺/收势/待机Ⅱ全扫，控制台无报错，角色身体与靴子无缺块。

### 5.17 倒地动作流畅性重接

把倒地从匀速切帧改为「失衡 → 下坠 → 触地缓冲 → 倒地待机 → 撑地起身」分段曲线，不改外观、碰撞与数值。

**状态链路**
- `death`（倒地过程，0.55s）：DD0 受击后仰 → DD1 踉跄 → DD2 跪地撑手 → DD3 坐倒 → DD4 翻身仰卧 → DD5 平躺。
- `dead`（倒地待机）：保持 DD5，叠加呼吸级 ±0.8px 起伏，布料逐渐停摆。
- `rise`（起身，0.4s）：倒放 DD5→DD0，撑地→抬头→收膝→回站，播完回 `idle`；起身中禁止攻击/跳跃/再受击。

**速度曲线与反馈**
- 倒地进度用缓动分段：前段失衡慢倾（0–30%）、中段加速下坠（30–70%）、后段触地收住（70–100%），不再按 14fps 匀速推帧。

- 起身段水平速度清零，镜头随起身回到中位。

**碎片清理（5.17 收尾）**：DD2 右侧 detached 翼/发块（821px）、DD3/DD4 地面脱靴碎片（198/124px）已按连通域抠除，三张重传 CDN 替换 `T.dd` 对应索引；DD0/DD1/DD5 与 DD3 抬起的腿为身体部分，保留。

### 5.18 放松态低频眨眼

仅在 `idle` / `idle2` 放松状态叠加低频眨眼，不动脸型、发型、身体与玩法数值。

**节奏**
- `blink = {t, next, closed}`：放松态累计 `t`，到 `next`（2.5 + rand×1.5s）置 `closed=true`，闭眼 0.06s 后睁开并重置计时；离开放松态立即复位 `closed=false`。
- 行走 / 奔跑 / 蹲 / 爬 / 跳 / 攻击 / 受击 / 倒地 / 起身均不眨眼。

**闭眼变体（非破坏式）**
- 每张帧在面部肤色带（y36–52、x80–118，含粉调肤色）定位上缘，在其上缘画 1px 压暗肤色的上眼睑线；**不擦除原眼缝与刘海像素**。
- 逐帧 diff 校验：每张 `closed` 变体相对原帧只改动 1–5px、且集中在同一行（y41–42），不产生面部孔洞。
- 早期方案用「深色眼点连通域 → 填周围肤色」，但近侧脸帧眼缝与刘海暗影连成一片，连通规则会误抠刘海、填出粉色斑块（已废弃）。

**已知限制**：眼睑是在既有精灵上程序化叠加的 1px 线，闭眼幅度有限；若要更饱满的闭眼 / 专注 / 发力 / 惊讶等表情，需要单独出闭眼与表情帧资产。其余面部表情切换本轮未做。

**`ATK_STYLE` 每招一套参数**（刀光形状 / 配色 / 火花数 / 顿帧 / 震屏 / 击退 / 扬尘 / 冲击环半径）：

| 招式 | 类型 | 刀光 | 配色 | 反馈 |
| --- | --- | --- | --- | --- |
| 一突 atk1 | stab 突刺 | 前伸细直刃 | 白 + 浅粉 | 轻顿帧、小震屏、少火花、无扬尘 |
| 二扫 atk2 | sweep 横扫 | 宽幅横扫弧 | 粉 | 中等震屏、中等火花、少量扬尘 |

### 5.20 像素清晰度与硬边渲染

针对“整体像素发虚”，从渲染管线做硬边化；不改角色造型与数值。

**管线修复**
- 所有离屏帧上下文（`paint` 绘制、布料分层 base/cloth、闭眼变体）显式 `imageSmoothingEnabled=false`，避免 0.8 缩放在离屏画布上被双线性柔化。
- 主画布每帧重述最近邻采样；角色 / 残影绘制坐标取整（`Math.round`），消除半像素偏移造成的边缘抖动。
- 去掉帧间半透明交叉融合（原 walk/run/crawl/idle2 末段叠下一张帧的重影），像素帧改为硬切。
- 取消起跳拉远的非整数 `zoom` 与攻击镜头前推 `camKick` 缩放，相机只做平移跟随 / 下压，不做非整数倍缩放，避免整幅画面重采样发虚。

**已知限制**：源精灵本身是 AI 生成的渐变 / 柔化 shading（翅膀、发梢存在相邻像素连续过渡的色阶斜坡），管线只能消除二次柔化，无法把已烘焙进素材的渐变变成硬边像素。若要真正锐利的像素块面，需要按硬边描边 + 限定调色板重新出整套帧资产；通道色阶量化与外轮廓描边在原型上试做过，对比弱、易弄脏暗部，未并入。

### 5.21 新帧只读预览面板（不改动原游戏）

### 5.25 全动作帧精修：黑块、白块、身形三件事

线上版本里很多帧「脸和身上像被黑块盖住」，逐个排查后确认是三个独立原因叠在一起，不是单一 bug。

**原因一：去底留了透明洞**。白底泛洪只从画面边界出发，被发丝、手臂、裙摆围住的白色区域进不去，于是留在帧里当成了「背景」被抠掉，露出后面深绿的森林色，看起来就是脸上的黑块。修法：泛洪之后再找「内部闭合的透明洞」，从原图把颜色补回去，并强制不透明（`refine_all.py` 的 `remove_bg`）。

**原因二：均值降采样把细节搅成暗块**。1536 缩到 124 时，一格里同时有深色发丝和肤色，取均值就得到一坨中间调的黑。修法：改成**块众数（bin-mode）降采样**——每通道 5bit 分桶，输出像素取源块里出现最多的那个桶，并取该桶的均值还原色相；只有不透明像素才计票。这一步之后脸能认出眼睛，像素格也清晰。对照过全局 40 色调色板版，那版整体发白，已否决。

**原因三：纯黑本身在深色场景里就是「洞」**。她的胸衣、手套、裙身是真的黑，压到 2px 之后和背景分不开。修法：加一道 `grade()` 调色——亮度 <28 的像素抬到深紫褐（36,25,33）并保留内部层次，28–72 的中间暗部乘 1.14。原画的黑布于是变成「有反光的黑布」，不再是洞。

**顺带修掉的白块**：奔跑、冲刺、跳跃几帧原画里烘焙了扬尘，被速度线围住的白色背景残块会原样留下，在游戏里就是一个白三角。修法 `drop_low_white()`：近白/低饱和、面积 >260px、重心落在画面下 26%、宽度不超半屏的连通块判为背景残块，直接置透明；围裙在上半身，被重心条件排除，不会被误伤。

**身形统一**：早期做法是逐帧把包围盒拉满 118px，结果躺倒帧被放大 2 倍、带特效的帧人物缩水。这一版改成**全局固定缩放** `SCALE = 0.0695`（1536 → 106），站姿落在 95–102px、躺姿自然变矮，跨状态切换不再跳大小，也正好对回引擎 `CHAR_H=80 / 角色 100px` 的标定。

**产出**：28 帧（idle3 / walk4 / run3 / jump3 / dash3 / attack4 / hit4 / down4），全部换成 CDN 新 token，主状态机的 `T.mi/wi/ri/ji/di/ai/hi/dn` 与预览面板 8 组同步替换。旧 token 留档在 git 历史与本文档 5.22 节，可回退。

**bug 1「冲刺回退」**：`finish()` 里 `dash → dashEnd` 写的是 `player.vx = DASH_END_V`（恒正），漏乘 `player.dir`。向右冲没问题，向左冲时突进段 vx=-360、收势段却 +250，角色 visibly 倒滑约 50px。修为 `player.dir*DASH_END_V`。实测左冲轨迹 x 单调递减 416→258，收势 vx -206→-60。
顺带消除同链路的「画风回退」：`dashEnd / rec1-4 / runBrake / runTurn` 原来仍吃旧源图（E/RC/BK/TN），新帧动作接旧画风收势像版本回滚；改为用新帧组合（冲刺收势→待机、攻击 pose→待机、奔跑→行走→待机），帧数保持 6/4/5/4/4/7/6 不变，并全部加入 `CLOTH_SKIP` 防布料误切。

**bug 2「倒下没对齐基线」**：帧对齐一直用包围盒底=基线 118。站姿没问题（最低像素=靴底），但躺/坐/跪姿的**尾巴尖、翼尖比身体接地点低 3px 左右**，把尖端压到基线就等于让身体悬空 3px（实测靴底离地约 8 逻辑像素）。修法：`refine_all.py` 增加 `CONTACT_GROUPS` 开关——down/hit 组改用「身体接触行」（不透明宽度≥8 的最低行）对齐基线，细尖端允许压到基线下方 1–3px（看起来像尾尖搭在地面前景）。重生成 8 帧后实测靴底贴地。


### 5.32 格挡三式接入状态机 + 木桩出招 AI

按 `格挡配置.json` v1.1 把 hold / parryLight / parryPerfect / break 四状态接进引擎：4 张关键姿（持守/外拨/卸力/崩防，去脚底灰投影 + 接触行基线）程序化铺帧 14/10/12/22，DEF 帧速 12/30/30/12，hold 循环。输入 F / 新按钮「格挡」：按下进 parryLight（parryT 计 tick），按住 ≥15 tick 转 hold；命中判定优先级 perfect(≤12 tick，全类型) > light(≤14 tick，仅 light) > hold(减伤 70%、耗架势 12/20/35、击退 6) > 吃满。架势归零崩防 22 帧锁输入，结束回 idle + 架势 30；空挥硬直 10/16 tick；脱防 24 tick 后 20/s 回架势。按住格挡键时受击/硬直结束自动重新架起 hold。

**木桩必须有出招 AI 格挡才有判定对象**：新增 idle→windup(0.55s 头顶粉条收缩预警)→strike 结算→recover 循环，轻/中/重轮换；被弹反僵直 0.5s、拍挡 10 tick。结算reach 110（hold 击退会把间距推到 96，原 95 阈值导致木桩打空气）。

自测 7 项全过：铺帧数、hold 扣架势减伤、perfect 弹反回架势+敌僵直、light 对 light 成功、light 对 heavy 吃满、空挥硬直、崩防→回 30；回归左冲单调/连段命中/跳跃落地全过，零 console 报错。测试要点：headless 按键有 10–30ms 延迟，拍挡窗仅 2 tick(33ms)，须先按键再按实测 parryT 反推 tel 设定命中时刻；场景间用 hook 把木桩 AI 停摆并复位间距，否则自然出招污染判定。

### 5.33 游戏 UI 重设计：HUD 血条牌 + 主机式按键 deck + 系统抽屉

旧 UI 是「顶部一排调试 tag + 底部圆钮混排」，调试信息与操作混在一起。重设计为三层：

1. **HUD**：左上角色牌（名字+当前状态 chip、分段像素血条/架势条，条内右端数字），右上连击牌（大数字 HIT + 累计伤害）。帧/朝向/FPS/方向检测移入顶部「遥测」细条，默认隐藏，抽屉里开关。
2. **按键 deck**（主机 bezel 风格）：左簇 ◀▶ 大方向键 + ▼跪爬/奔跑按住小键；右簇 2×2 街机四键（跳跃 teal / 冲刺 gold / 格挡 ice / 攻击 pink 最大），每键配色对应功能、按压下沉 3px + 硬阴影收 1px；`bindBtn` 现在 press 加 `.on`、release 移除，触屏按住有持续高亮（旧版只有 :active，touch 不可靠）。中簇仅 ♪/全屏/横置 三 chip。
3. **系统抽屉**：舞台右下 ⚙ 打开右侧滑入抽屉，收纳帧速滑块、新帧预览、遥测开关、待机Ⅱ/受击/倒地/复活测试键与规格全文；舞台不再被 details 占角。

自测 7 项：触屏点攻击命中、触屏按住格挡进 hold 且 .on 高亮、触屏左移、抽屉+遥测开关、血条/架势条宽度联动（架势会回所以断言留回复区间）、竖屏自动横置、deck 不溢出；零 console 报错。键盘绑定全部保留不变。

### 5.34 攻击动作优化：蓄力→出手→延伸→随势 + 前冲步

旧攻击每段只有 2 帧同一姿态硬切（`F.atk1=[AI0,AI0]`），没有蓄力/随势，出手时 `vx=0` 原地打拳，缺重量感。重做为四帧节奏（四段 4/4/4/5 帧 @24fps）：

- **帧节奏**：f0 蓄力（`dx-3,tilt-0.05` 微后坐）→ f1 出手（`dx+2,tilt+0.05`）→ f2 延伸（`dx+5,tilt+0.08`）→ f3 随势（`dx+2,tilt+0.02`）；四段加 f3 二次发力（`dx+7`）。收招首帧改从随势姿回正，不再从出手姿硬跳待机。
- **前冲步**：新增 `ATK_LUNGE`（220/190/170/260），出手帧给 `dir*ATK_LUNGE` 前冲、随势帧衰减 40%，蓄力帧微后坐 -30；收招帧速度线性归零。整段连击实测净前移 33px 且 x 单调不回滑。
- **残影**：出手帧 push 一条 afterimage（life 0.22），复用冲刺残影系统。
- **判定/刀光对齐**：`ATK_WIN` 四段改 [1,3]，`drawSlash` 窗口起点同步从 `win[0]-1` 改 `win[0]`，弧光只在出手/延伸帧出现。

自测：帧数 4/4/4/5、四段连段齐全、4 次命中（130→64）、前冲 33px、无回滑、收招回待机、格挡/冲刺回归通过；零 console 报错。注意命中判定 reach 用 `dummy.x`（不含弹簧 dx），起始间距 >reach+38 时前两段会挥空——属预期射程，非 bug。

### 5.35 场景延伸重做：全宽世界取代重复平铺

第一版延伸用「960 图层横向平铺 + 相机跟随」，但同一块图重复出现（月亮/巨木/空地每 960px 复制一次），右尽头还因相机平移与视差偏移重复计算露出黑边。重做为**全宽世界**：

- `WORLD_W = canvas.width*2`（1920），五层背景（sky/far/mid/ground/fg）直接按 `WORLD_W` 程序化生成，**不再平铺**，月亮只有一轮、巨木/月光空地/光柱/萤火/落叶/雾带全程分布不重复。
- 中部加一对巨木框第二块空地，右段 `w*0.68` 加第二块月光空地，避免右半世界空旷。
- **变换拆分修黑边**：背景层在身份坐标系内按视差系数 `fPut` 偏移绘制（不吃实体平移），实体（木桩/角色/特效）才吃 `ctx.translate(-cam.x)`。旧版两者叠加导致右尽头背景错位露黑。
- 相机水平跟随 `cam.tx=clamp(player.x-canvas.width/2, 0, WORLD_W-canvas.width)`，玩家边界放宽到 `[40, WORLD_W-40]`。

自测：世界宽 1920、左右边界与相机 clamp 正确、右尽头整行不透明（无黑边）、木桩仍可命中、格挡/攻击连段/冲刺/跳跃回归通过；零 console 报错。三位置截图确认背景连续、单月视差漂移、无平铺重复。

### 5.36 丛林→平原群系渐变

世界按位置做连续生物群系过渡：`biomeAt(x)` 用 smoothstep 在 `BIOME.from=720`、`span=560` 区间把丛林因子 0 平滑到平原因子 1，各层按世界坐标逐列混合，无硬边分界。

- **远层**：冷杉随群系逐渐稀疏（平原侧概率门控），叠加低矮缓丘剪影与受光脊线。
- **中层**：右巨木移除、树冠/垂藤限丛林段；平原段只留零散矮灌。
- **地面**：平原草甸（浅绿草面+亮边+偏浅土层）按 alpha 逐列覆盖林地基质，点缀粉/白/黄野花；蘑菇、蕨类、倒木、板根等丛林锚点固定在左侧林段。
- **前景**：林草限丛林段，平原段换短草；右侧暗枝叶按群系关闭。
- **天空**：平原侧整体略亮偏暖一档。

自测：三位置（丛林/过渡/平原）截图确认植被、色调、地面连续过渡；世界坐标地面色扫描无跳变；冲刺/跳跃/攻击连段回归通过（木桩 130→109）；零 console 报错。

### 5.37 背景光影精修

在保留像素硬边与夜景基调的前提下，分层打磨背景光照：

- **月亮**：补一圈更淡的外层光晕；月光沿林隙向下渐宽下泄；几颗亮星带十字芒。
- **光柱**：由单一边条改为「边翼+亮核心」双层体积光束，随风轻摆、脉冲呼吸，落地处留一块淡光斑。
- **地面**：月亮正下方补一块被打亮的软光水洼池；地面雾从三层加到五层、近地更亮。
- **萤火**：光晕由 5px 扩到 7px 双层，核心暖色更亮。
- **压暗**：背景四角与顶部叠加渐暗边，聚拢视线；实体不受压暗影响。

自测：三位置截图确认光影层次连续、无过曝；冲刺/跳跃/攻击连段回归通过（木桩 130→109）；零 console 报错。

### 5.38 跪爬对角步态 + 冲刺手感重做

**跪爬**：旧 u 组 4 帧旧画风换成 3 张 clean 关键帧（A 左手+右膝前伸 / 中性收拢 / B 右手+左膝前伸），`F.crawl` 按 `[A,收,B,收]` 铺成 **80 帧对角循环**，bob/dx/tilt 随相位起伏。移动速度 `SPEED*.45`（≈68，低于行走 150）。低姿态碰撞盒：`resolveDummyHit` 中 crawl 躲开 mid/heavy 高位攻击（light 仍命中）。取消规则：爬行可起身行走/跳跃/格挡，**不可直接冲刺**（`dash()` 排除 crawl）。

**冲刺**：
- 速度曲线：dash 6 帧按 `prof` 蓄力(0.35/0.67)→爆发(1.0)→过渡(0.8)，非瞬间启停；dashEnd 惯性衰减回正。
- 无敌帧：dash **前 3 帧**闪避（`resolveDummyHit` 顶部判定，飘「闪避」），第 4 帧起吃满。
- 架势：冲刺耗 12，`guardDelay=0.4` 覆盖 dash/dashEnd 全程，结束后延迟 0.4s 才恢复。
- 取消：突进(dash)可接攻击/弹反尝试；收势(dashEnd)只能基础格挡（`defendPress` 直转 hold）、不可二次冲刺；落地无缝接行走/跪爬（`finish` dashEnd 按 input.down 转 crawl）。

自测：80 帧、降速 68、爬行禁冲刺、躲高位 hp 不变；冲刺耗架势 100→88、前 3 帧 hp 不变/第 4 帧 -22、突进→atk1、收势→hold、收势禁冲刺；四段连段 130→73、长按格挡减伤耗架势回归通过；零 console 报错。

### 5.39 跪爬体型统一

新跪爬关键帧初版按全局 `SCALE=0.0695` 对 bbox 高度归一，但跪爬是横向姿态、bbox 高度天然小，导致角色整体比待机/冲刺小约 0.8 倍。改为 `SCALE×1.25`（0.0869）重精修三帧，使头部/躯干与站姿动作同比例，仅姿态压低；接触行基线不变，脚膝贴地。自测：80 帧、零报错，待机/跪爬/冲刺三态截图体型一致。

### 5.40 跪爬步态修正：趴低对角爬

5.38/5.39 的跪爬关键帧躯干偏高、像「跪坐伸手」，膝盖没有明显前后交替，不合格。重做关键帧：以「hands-and-knees crawl、背部接近水平、头前伸不高抬、两膝一前一后错开 + 对角手前伸」强约束生成 A 相，再以 A 为参考镜像出 B 相与中性过渡相（保证三相身体高度/体型一致），1.25× 精修。`F.crawl` 仍按 `[A,收,B,收]` 铺 80 帧。自测：80 帧、跪爬躲高位 hp 不变、四段连段 130→73、零报错；循环 filmstrip 与实机截图确认趴低对角爬步态成立。

## 六、精灵帧接入经验

1. 源图先**去白底 → 裁边 → 归一高度 → 对齐基线**，再接入；基线不齐会导致帧间上下抖动。
2. 起步 / 收步复用待机帧，奔跑复用走路关键姿，减少重复补帧。
3. 反步帧、对角交叉爬行帧单独补出；循环帧用 `slots()` 按比例拉伸到目标帧数，循环点首尾衔接。
4. 同一动作分组编号（m 待机 / n 待机Ⅱ / v 走路 / p 蹲下 / o 跳跃 / u 匍匐 / z 奔跑 / bk 急刹 / tn 转身 / at 攻击 / rc 收招 / ht 受击 / dd 倒地），接入时按 key 映射，不要在 HTML 里散落单张图 URL。
